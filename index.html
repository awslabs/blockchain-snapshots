Blockchain Snapshots on AWS

GitHub

Skip the initial sync: bootstrap your node from a pre-synced snapshot in Amazon S3.

Each snapshot is a copy of a node database from the network's upstream publisher, refreshed on their schedule. Download one to an EC2 instance in the same Region and start your node from it. There is no charge for the snapshots. Standard charges apply for the instance and storage you use.

Get started

Snapshots are only reachable through an Amazon S3 gateway VPC endpoint, so you download them from an EC2 instance in the same Region. A laptop or a browser won't work.

  1. Use an instance

    Run these steps on an EC2 instance in us-east-1, eu-west-1, or ap-northeast-1, running Amazon Linux 2023 or Ubuntu 24.04. Its VPC needs an S3 gateway endpoint, and its instance profile needs s3:GetObject and s3:ListBucket.

    Storage can be either local NVMe (instance types like i4i or i8g — fastest) or an EBS volume large enough for the extracted snapshot. Step 3 covers both.

  2. Get the tools and dependencies

    Setup installs:

    • AWS CLI v2
    • Python 3 with boto3 and zstandard
    • zstd, tar, curl, and unzip
    • mountpoint-s3 and FUSE when the instance supports them; otherwise downloads use S3 directly

    First get the repository. Amazon Linux 2023:

    sudo dnf install -y git
cd ~ && git clone https://github.com/awslabs/blockchain-snapshots.git
cd blockchain-snapshots/dist

    Ubuntu 24.04:

    sudo apt-get update && sudo apt-get install -y git
cd ~ && git clone https://github.com/awslabs/blockchain-snapshots.git
cd blockchain-snapshots/dist

    Then run setup once:

    ./snapshot.sh --setup

    Setup may prompt for sudo. Snapshot download commands do not use sudo; run them as the account that should own the data. AWS Blockchain Node Runners uses bcuser.

  3. Set up storage

    Extract to a dedicated directory on a volume with room for the full snapshot. Pick the one that matches your instance.

    Local NVMe — join the instance's NVMe drives into one volume at /data:

    sudo bash setup-storage.sh

    EBS volume — no RAID needed. If it's an extra volume (here /dev/nvme1n1), format and mount it once; if you're using the root volume, just make the directory:

    sudo mkfs.xfs -f /dev/nvme1n1          # skip if already formatted
sudo mkdir -p /data && sudo mount /dev/nvme1n1 /data
sudo chown "$(id -u):$(id -g)" /data

    On EBS the extractor writes buffered automatically; on local NVMe it uses O_DIRECT. Either way the result is identical — size the volume for the snapshot's extracted size, not its download size.

  4. Download a snapshot

    Pick a snapshot below and run its command from the dist folder. snapshot.sh resolves the latest catalog entry at execution time, checks storage, and selects the delivery method from catalog data. Each snapshot writes to its own folder under /data.

    For archive-set snapshots such as Solana, the files remain compressed because the node unpacks them itself. Start Agave with --snapshots pointing at that folder and --no-snapshot-fetch.
